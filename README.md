# Dynamic Digital Menu

A production-oriented restaurant menu and management dashboard built with Next.js App Router, TypeScript, MongoDB Atlas, Auth.js, Cloudinary, Zod and Tailwind CSS.

## Features

- Public mobile-first menu with search, categories, availability, discounts, badges, sizes and extras
- Protected administrator dashboard using secure HTTP-only sessions
- MongoDB-backed category, product and restaurant APIs
- Product creation and editing, signed image uploads, filters, pagination and safe deletion
- Downloadable permanent menu QR code
- Responsive desktop, tablet and phone layouts

## Installation

1. Install Node.js 20 or newer.
2. Run `npm install`.
3. Copy `.env.example` to `.env.local` and complete every value.
4. Run `npm run seed` to create the administrator, restaurant record and categories.
5. Run `npm run dev` and open `http://localhost:3000`.

The public menu is at `/menu` (also available at `/`). Administration begins at `/admin/login`.

## MongoDB Atlas setup

Create an Atlas cluster and database user. Add a database name such as `dynamic-menu` to the connection string and save it as `MONGODB_URI`. Configure Atlas network access for development and Vercel. The seed command creates initial records and stores the administrator password only as a bcrypt hash.

## Cloudinary setup

Create a Cloudinary account and add its cloud name, API key and API secret to `.env.local`. Images are validated for type and size, then uploaded using a short-lived signature generated by an authenticated server route. The API secret is never returned to the browser.

## Vercel deployment

1. Push the project to a Git provider and import it into Vercel.
2. Add every variable from `.env.example` under Project Settings → Environment Variables.
3. Set `NEXTAUTH_URL` to the final HTTPS domain and generate a strong `AUTH_SECRET`.
4. Deploy using the standard `npm run build` command.
5. Run `npm run seed` once against the production database from a trusted machine.

Never commit `.env.local`, MongoDB credentials, Cloudinary secrets, Auth secrets, or administrator passwords.
